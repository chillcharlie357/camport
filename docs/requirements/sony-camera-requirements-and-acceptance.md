# Sony 相机导入：需求与验收标准

版本：1.1，2026-11-10。用途：产品范围、实现约束、测试和发布验收的统一依据。最新用户要求优先于历史设计稿。

> **最高优先级：无线预览加载。进入图库不得把相机中的原图全部传到设备。浏览、滚动、筛选、合并显示和评分都必须以文件信息、按需缩略图和本地缓存为基础。**

## 1. 目标、范围与优先级

解决 Imaging Edge Mobile / Monitor+ 连接不稳定、图库预览慢、导入效率低和返回后台后恢复困难的问题。首版先完成照片浏览、预览、挑选和原始文件导入；第一代 ZV-E10 + Android 为首批实机验证组合，架构面向 iOS、Android、macOS、Windows。

- **P0**：首版发布必须满足；损坏原片、越权、泄露凭据、浏览触发整卡原图下载等属于阻塞发布问题。
- **P1**：该平台版本正式发布前必须满足；可按平台分阶段交付。
- **P2**：后续需求，未纳入首版承诺。
- **硬性约束**：行为与正确性必须满足，不依赖相机性能。
- **性能目标**：下面数值是初始工程预算，不是已测成绩；相机与网络有关的指标须先采集基准，再冻结为该兼容组合的发布门槛。不得因为尚无基准而将指标记为通过。

首版不包括实时监看、遥控拍摄、USB 传输、云账号与云备份。已有付费软件仅用于理解兼容协议，不绕过购买或激活检查，不复制其代码与品牌资产。

## 3. 功能需求

### 3.1 连接与机型能力

| F-CON-03 | P0 | 按能力开放操作 | 文件列表、缩略图、预览、原片下载分别确认能力；不可用时有说明，不仅凭型号名称宣称支持 |
| F-CON-04 | P1 | 本地保存相机档案 | 重启后保留档案；忘记相机清除关联凭据；同名相机由可用设备标识区分 |

### 评分写回决策（2026-11-10 用户补充）

用户明确允许评分改动**本机原文件和相机卡内原文件**。一次评分操作即表示应用此期望评分到这两类可用、可写的目标；不需要每次重复确认。授权限于评分元数据，不扩大到图像重编码、文件删除或其他相机设置。

本机原文件使用经过格式验证的元数据写入方式；相机端先验证该型号/固件/当前连接模式的评分命令。相机菜单具备评分功能并不等于已验证远程写回接口。缺少能力、写权限、导入文件或连接时保留期望评分与未同步原因，不能自动退回本机数据库却标为成功。

若目标相机不支持远程评分，必须记录为该机型的写回能力缺口，不能把“不支持”算作双目标写回验收通过。

当前程序仍仅保存本机期望评分，**尚未实现本机媒体元数据或相机端写回**。本次更新授权、设计与验收规则，不把现有 19 项测试作为原文件写回已完成的证据。

**固定验收样本**：6 个 RAW、13 个 JPEG、1 个 PNG、4 个视频，共 24 个文件；其中 5 对 RAW/JPEG、1 对 RAW/PNG。展开 24 项，合并 18 项；RAW 6、JPEG 13、PNG 1、MP4 4。另测 `IMG_1.ARW + img_1.JPG + IMG_1.PNG`、不同目录同名、孤立 RAW、仅 JPG/PNG、空名、名称多点号和超长文件名。

| 编号 | 优先级 | 需求 | 验收标准 |
|---|---|---|---|
| F-IMP-01 | P0 | 只导入用户选择的文件 | 包含 RAW/JPEG/PNG/视频混选用例；未选文件无原片请求；预览导入明确指出当前成员，图库合并项导入明确指出成员数 |

| F-IMP-03 | P0 | 临时文件与完成发布 | 下载中不作为完整照片出现；成功校验后才发布。跨卷/系统相册发布使用安全提交或平台的待发布状态，不假设任意位置都可原子重命名 |
| F-IMP-04 | P0 | 队列可恢复 | 入队后保存任务状态；重启可找到未完成任务；支持暂停、取消、失败重试；已完成文件不重复下载，未完成文件不伪报成功 |

| F-IMP-06 | P0 | 空间和目录异常 | 空间不足、目录不可写、权限撤销、目标盘移除时有明确原因；保留完成项，安全处理临时文件；重试不创建重复完整项 |
| F-IMP-07 | P0 | 支持大文件 | 使用流式读写；超过 4 GiB 视频不截断、不整数溢出；进度基于已收到字节；内存不随文件总大小线性增加 |
| F-IMP-08 | P1 | 平台保存入口 | 手机支持本机文件，系统允许时明确授权保存相册；桌面选择目录。相册不接受的 RAW/格式可保存为文件，不擅自转码 |

## 4. 无线预览架构与请求预算

### 4.1 请求路径

```text
连接相机 → 读取能力和目录元数据 → 渲染文件卡片
                                ↓
                    命中本机缩略图？→ 立即展示
                                ↓ 未命中
               仅请求可见卡片缩略图 + 至多下一行预取
                                ↓ 用户打开一张
               缓存小图 → 按需预览图 → 用户手动载入原图
                                ↓ 用户明确导入
                         流式下载选中原文件
```

下面是首版无线请求预算，不代表所有相机接口都已证实存在：

| 项目 | 初始预算 / 硬性限制 | 验收方式 |
|---|---|---|
| 原片自动预取 | **0 请求、0 原片字节**；浏览和评分不读取原片来做缩略图 | 记录端点类型/文件 ID/触发动作/响应字节，逐操作审计 |
| 同时进行的缩略图请求 | 默认最多 2 个 | 注入每请求 500 ms 延迟，抓取同时在途数量 |
| 后续缩略图预取范围 | 最多可见区域后紧邻一行；手机两列时最多 2 项 | 停留在首屏 60 秒，列表含 1 万项，仍不得持续把后续图排入队列 |
| 缩略图去重 | 同一文件版本同时最多 1 个；合并卡片优先只取一个代表成员 | 重复滚动、重复打开和切换合并时核对请求计数 |
| 优先级 | 当前单张预览 > 可见区缩略图 > 下一行预取 | 新预览到达后不排在整卡缩略图队列尾部；已在途的有限请求允许完成 |
| 导入时资源竞争 | 暂停下一行预取；可见缩略图并发降至最多 1；原片默认串行 | 对比只导入与同时浏览吞吐，报告变化；不能无依据提高并发 |
| 本地缩略图尺寸 | 初始上限长边 512 像素；预览图独立缓存 | 检查缓存与解码尺寸。相机只提供较大图时记录接收成本，本地缩放不算节省无线流量 |
| 缩略图缓存 | 初始磁盘上限 256 MiB，LRU；可清理 | 压满后缓存有界；清理不删除导入文件、评分或队列 |
| 无缩略图能力 | 占位 + 说明；原图必须手动请求 | 禁用服务端缩略图端点，确认不会回退为整卡原图下载 |

目录扫描与缩略图获取分别计时、计流量。相机若必须返回整份**元数据**清单，不等同于允许传输整份**图片内容**；报告中必须明确区分。

## 5. 性能需求与测量方法

### 5.1 指标定义与优先次序

首先保证 F-PRE-01/F-PRE-05 的流量约束，再优化用户可见延迟。先让用户看到可用的缩略图，不等待所有图片齐全。

- **冷图库首图**：相机协议已就绪到首个可见缩略图完成解码并绘制；包括元数据等待、请求排队、网络、解码和绘制。
- **暖图库首图**：进入已有有效缓存的图库到首图绘制；同时记录相机请求数。
- **冷连接到可用图库**：用户点连接到至少一张可见照片且可操作；系统权限/用户操作等待单独列出，不隐去总耗时。
- **预览可见延迟**：点卡片到首个可用预览绘制；命中小图时先显示小图，高清预览另报完成时间。
- **有效吞吐**：成功发布的原始文件字节 / 传输阶段耗时；另报端到端耗时和重试字节，不能用网卡链路速率代替。
- 使用 P50/P95；初期每组至少 30 次样本，记录全部样本、最差值和失败数。已有产品比较使用相同定义。

### 5.2 初始性能预算

下表均为待验证的初始目标，**不是当前通过的验收成绩**。不受相机影响的本地指标可先冻结；真机指标在建立基准后由测试报告记录最终门槛与原因。

| 编号 | 优先级 | 场景 | 初始目标 / 门槛 | 测试条件 |
|---|---|---|---|---|
| P-PRE-01 | P0 | 有缓存的图库首图 | P95 ≤ 300 ms；同一版本缩略图请求 0 次 | 本机有首屏有效缓存，冷开/热开分别记录，原片请求必须 0 |
| P-PRE-02 | P0 | 已连接相机的冷图库首图 | 初始目标 P95 ≤ 2 s；真实接口能力需验证 | 1,000 文件库，缓存清空、设备距相机约 1 m、记录频段与信号；不得下载原片换取“达标” |

### 10.1 性能报告必须包含

应用提交/构建模式、OS 与硬件、相机型号/固件/存储卡、无线频段/信号/距离、文件清单与数量、冷暖缓存定义、测量起止点、样本数、P50/P95/最差值、失败数、元数据/缩略图/预览/原片请求数和字节、缓存命中率、峰值内存、帧耗时。比较 IEM/Monitor+ 时保持这些条件一致，并记录对照版本。

每项记录：需求 ID、用例、实际结果、通过/失败/未执行、不适用原因、证据路径、执行日期与执行人。未执行不能填通过；能力不支持须同时记录用户可见降级行为。

### 10.2 首版发布门槛

1. 正式发布的组合须通过全部适用 P0 与 P1；预览版可以逐项公开未完成的 P1，但必须标为预览版，不能宣称通过正式发布验收；不得隐藏失败。
2. **A-01/A-03/A-06 必过：浏览不触发整卡原图下载，预览优化不靠全量预下载。**
3. 传输字节完整性 100%；显式评分写入仅允许评分元数据变化、图像数据保持一致；无静默覆盖、误删、路径越界或凭据泄露。
4. 故障与后台测试后队列可恢复；系统禁止继续时状态说明准确。
5. 真机性能基准和最终门槛已归档；预览性能未实测时不得标注“已优化达标”。
6. 无未解决的阻塞缺陷和适用的严重/高风险安全问题；签名、许可证与兼容矩阵齐全。

## 11. 决策和变更管理

- 用户批准 v2 银灰视觉；基线提交 `6c4db3b`，通过校验清单追溯，功能增补不覆盖该快照。
- 用户要求按同名简单合并 RAW 与 JPG/PNG，不增加复杂的拍摄身份要求。
- 用户后续明确允许评分写入本机和相机原文件；该决定覆盖此前“评分仅本机、不写原文件”的限制。
- 用户明确预览加载速度优先，尤其无线连接；禁止为了预览而全量传输相机图片。
- 性能数值目前为初始预算；最终真机门槛变更须在报告中写明原因、对照数据和对应需求 ID。
- 发生冲突时，以本文件和最新明确用户决策为准；历史图稿/旧计划须同步修订，不能反向覆盖新规则。
